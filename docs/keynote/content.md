# Event keynote content

## Purpose

Welcome attendees to **Dev Days Cape Town 2026**, recognize the Cape Town MS
Dev User Group community that made the event possible, orient everyone for the
day, and give a high-energy overview of the GitHub Copilot ecosystem.

The keynote is not a GitHub Copilot App product tour. The App is one important
part of a larger story that includes IDE experiences, Copilot CLI, GitHub
Copilot cloud agent, GitHub.com, GitHub Mobile, customization, automation, and
the platform developers can extend.

## Audience promise

By the end of 30 minutes, attendees should understand:

1. What the event offers and how to make the most of the day.
2. How Copilot has expanded from code completion into planning, implementation,
   review, delivery, delegation, and automation.
3. Why the IDE, terminal, GitHub, mobile, and Copilot App experiences have
   different execution boundaries.
4. Where human judgment, repository checks, permissions, and review remain
   essential.
5. Which later session or workshop can take them deeper.

### 9. Work locally: IDE Agent and Plan modes

**On slide**

> Ask when you need an answer  
> Plan before a consequential change  
> Use Agent mode to implement and verify

**Audience takeaway**

The IDE is the immediate, visible, local workflow. Support varies by editor, so
use VS Code as the concrete demonstration rather than implying perfect feature
parity everywhere.

### 10. Work from the terminal: Copilot CLI

**On slide**

> Plan locally  
> Grant tools deliberately  
> Delegate when the work should continue

**Audience takeaway**

Copilot CLI is an agentic terminal workflow with planning, permissions, code
changes, debugging, GitHub interaction, and an explicit `/delegate` path to
GitHub Copilot cloud agent. A normal CLI session executes on the local
machine.

---

### 11. Let work continue: GitHub Copilot cloud agent

**On slide**

> Assign a task  
> Follow the pull request  
> Keep normal repository gates

**Audience takeaway**

The cloud agent works asynchronously in a GitHub-hosted environment and
prepares changes through a branch and pull request. Permissions, CI, review,
and branch protections still matter.
